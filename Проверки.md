# Результаты проверки программной части СРС №7

Проверено 13 ноября 2026 года в Python 3.14.4, Django 6.1.3, DRF 3.18.3. Браузерные сценарии — Playwright 1.65.1 и Chromium. Это результаты автоматических проверок, а не утверждение о выполнении ручной приёмки или подготовке отчёта.

## Итоговые команды

| Проверка | Результат |
| --- | --- |
| `.venv/bin/python manage.py check` | Ошибок конфигурации нет |
| `.venv/bin/python manage.py makemigrations --check --dry-run` | Неучтённых изменений моделей нет |
| `node --check equipment/static/equipment/app.js` | Синтаксических ошибок нет |
| `RUN_BROWSER_TESTS=1 .venv/bin/python manage.py test` | **47 тестов прошли**, пропусков нет: 38 серверных (включая 9 исходной ПЗ №7), 9 браузерных |
| `.venv/bin/python manage.py migrate` | Миграции применены к отдельной демонстрационной БД |
| `.venv/bin/python manage.py seed_equipment_demo` | Созданы 4 экземпляра, 7 бронирований, события и два обычных аккаунта без начальных паролей |

Исходники ПЗ №7 сохранены. Проверки работают на тестовой БД, а не на демонстрационной. Для LiveServer используется отдельная файловая SQLite, уничтожаемая штатным тестовым runner после выполнения.

После упрощения интерфейс использует последовательные загрузки и одну блокировку элементов управления вместо счётчиков актуальности запросов. Учебные инвентарные номера — `НБ-001`, `НБ-002`, `ПР-001`, `ПР-002`.

## Восемь проверок ТЗ

| № | Сценарий | Подтверждение и результат |
| --- | --- | --- |
| 1 | Создать объект и начальное событие | API-тест проверяет владельца, статус и событие; Chromium создаёт запись через форму — пройдено |
| 2 | Разрешённый переход | API и Chromium выполняют подтверждение → выдачу → возврат; проверяются оборудование и журнал — пройдено |
| 3 | Запрещённый прямой запрос | API отклоняет выдачу из `new`, повторные действия и подмену статуса; снимки записей и истории не меняются — пройдено |
| 4 | Сбой составной операции | Тест создаёт событие и выбрасывает исключение внутри операции; откатываются бронирование, оборудование и событие — пройдено |
| 5 | Другой пользователь | API проверяет чтение, изменение, удаление, все actions и историю; реальный вход второго пользователя в Chromium показывает только его записи — пройдено |
| 6 | Подтвердить или отменить удаление | Chromium проверяет отсутствие DELETE при отмене и удаление после подтверждения; API проверяет 204, скрытие записи и сохранность истории — пройдено |
| 7 | Обновить страницу | Chromium повторно загружает завершённую запись и историю после reload; отдельный API-клиент видит сохранённые данные — пройдено |
| 8 | Два фильтра | API проверяет параметры отдельно и совместно; Chromium проверяет URL с обоими параметрами и пустой результат — пройдено |

Дополнительно проверены: логическое удаление и запрет физического каскадного удаления; редактирование и отсутствие лишнего события при PATCH того же значения; отмена с освобождением ресурса; запрет второй брони занятого экземпляра; явный отказ на служебные поля; CSRF; ошибки 400, 403, 404, 500, сеть и не-JSON ответ; безопасный текстовый вывод; различие успешного изменения и сбоя обновления; выход из аккаунта; ширина 390 px; сохранение старых страниц и тестов портала; безопасное повторное наполнение демонстрационного набора.

Ошибки сети и сервера в браузерных тестах имитируются перехватом ответов только внутри тестов. Учебный сбой транзакции не доступен через публичный API.
